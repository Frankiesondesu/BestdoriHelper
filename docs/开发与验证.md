## 开发

```bash
pytest                          # 单元测试（318 个，全部离线，约 16 秒）
python scripts/e2e_check.py     # 端到端：合成模拟截图跑完整识别链路
python scripts/edge_cases.py    # 边界场景：auto 切分 + 属性提示 A/B
python scripts/gui_check.py     # 桌面界面自检（窗口显示 3 秒后自动关闭）

# 网页版（先起本地服务）
python -m http.server 8788 --directory docs
python scripts/site_check.py    # 真实浏览器跑一遍「上传 → 识别 → 出清单」
python scripts/site_check.py --device "Pixel 7"    # 手机视口 + 横向溢出体检
node docs/build/verify_detect.mjs    # JS 切分：不传 region 能否切出 28 格
node docs/build/verify_cells.mjs     # JS 检索：140 个真实格的结果
node docs/build/verify_selfcheck.mjs # JS 指纹库自洽性

# 安卓 App
python scripts/export_codec_cases.py && node docs/build/verify_codec.mjs
                                     # Bestdori 编解码：Python 与 JS 逐字节比对
python scripts/sync_check.py         # 同步链路（mock 网络，不需要真账号）
npx cap sync android                 # 网页资源同步进安卓工程
```

- **`pytest`** —— 覆盖特征提取、网格切分、指纹库、清单、导出、导入计划、识别流水线、卡图来源与属性提示，
  以及桌面界面（`test_gui_smoke.py` 用 Qt 的 `offscreen` 平台把窗口真正建出来，
  并走一遍「人工修正识别结果 → 清单同步改写」等关键路径）。未装 PySide6 时自动跳过 GUI 部分。
  全部用程序合成的假卡面，不联网、不依赖预先存在的指纹库。
- **`e2e_check.py`** —— 建小规模指纹库 → 合成 7 组不同难度（缩放 / JPEG 压缩 / 亮度色偏 /
  极小图 / 取景偏移）的模拟截图 → 跑识别 → 输出准确率。合成格严格按真实游戏格来：
  **正方形、尺寸正好等于画布等分、卡框按真实属性上色并带右上角属性图标**。
- **`edge_cases.py`** —— 专测 `auto` 自动切分（有/无背景间隙、粗细边框、UI 叠加）
  与属性提示的开/关对照。
- **`gui_check.py`** —— 在**真机**（非 offscreen）上把窗口显示出来，验证 Qt 平台插件、
  字体与主题可用。

## 编组算法

编组（`docs/src/team.js`）的正确性**不靠读文档**，而是把 Bestdori 组队工具自己的
计算引擎切出来在 Node 里跑，喂同一份输入比数字。

```bash
node scripts/team_vs_bestdori.mjs          # 11 组断言：卡面 / 评级 / 道具 / 综合力 / 分数 / 点数 / 支援
node scripts/team_vs_bestdori.mjs --all    # 卡面全量（2490 张），默认抽样 400
node scripts/team_vs_bestdori.mjs --refresh  # 重新抓 Bestdori 的 JS

node scripts/score_vs_bestdori.mjs         # 分数逐位对拍：24 谱面 × 5 技能类型
node scripts/score_vs_bestdori.mjs --prate=0.95 --diff=hard

node scripts/area_pick_check.mjs           # 区域道具：6 条曲线 × 叠加 × 逐槽位二选一
node scripts/team_alg_check.mjs            # 组队搜索：公式断言 + 排序
node scripts/team_prune_check.mjs          # 粗排剪枝：代理值与精确值的差距上界
node scripts/team_render_check.mjs         # 结果渲染
```

### 依据来源分三层，别混

| 层级 | 例子 | 可信度 |
| --- | --- | --- |
| **可执行代码** | `ct()` 的 120 项排列数组、`ut()` 的连击表、`it()` 的 9×7 道具槽位 | 最高，直接对拍 |
| **官方 API 数据** | `/api/songs/all.json` 的 `notes`（连击数）、`/api/skills/all.10.json` 的 `activationEffect` | 高，可全库校验 |
| **社区文档 / 反编译** | 各家计算器文档、IL2CPP 反编译结论 | 需逐条核实，不采信为默认 |

第三条尤其要注意：外部文档说的机制**不一定在 Bestdori 里实现**，而本站的对齐目标是
Bestdori。实测两条差异：

| 外部文档的说法 | Bestdori 实际 | 实测影响 |
| --- | --- | --- |
| 单曲用 1024 条随机路径 / 96 种顺序的加权分布 | `ct()` 是 **120 项手写排列 + `C/120` 平均** | 0.048% 平均，0.099% 最大 |
| 技能结束后 **0.75 秒排队**才开始下一个 | `lt()` 里**没有**排队，`d = 触发时刻 + 时长` | 0.10% 平均，0.65% 最大（仅 0.7% 谱面会触发） |

两条都**不实现** —— 对齐目标就是 Bestdori，而且代价比收益大。

### 已知的、有意保留的差异

1. **区域道具**：Bestdori 的模型是「9 个乐团组选一个」（`i.band` 是 9×7 的槽位表），
   选一组就锁死 7 个槽位。游戏实际是**逐槽位二选一**（可以「大家的键盘 + 多惠的吉他」），
   本站按游戏规则实现，因此跨乐队队伍能算出比 Bestdori 更高的综合力。
   对拍 Bestdori 时用「9 选 1」那一支。
2. **动态技能倍率**：站点把技能压成固定 `{d, up}`，Bestdori 的 `st()` 会按连击数/
   判定条件逐音符算倍率。按卡池占比加权，P=100% 时总偏差 -0.055%，P=90% 时 +0.69%。
   不值得为它重写计分内核。
3. **综合力取整**：Bestdori 用 `Math.floor(五张卡之和)` 后计分，本站也对齐了
   （不取整会多 0.1~0.6 点）。

### 支援乐队（Mission Live 的组合加成）

规则照抄 Bestdori `ToolTeamBuilder.js` 的 `X()`：从**全部卡池**按单卡综合力降序贪心，
取满 5 个不同角色为止，跳过主队已用的卡。支援综合力**不含区域道具**，
贡献 `floor(综合力 / 3000)` 点。

顺序很重要 —— 支援项**不被活动加成放大**，但在火倍率之内：

```js
ep = floor(base * (1 + bonusSum)) + floor(supportPower / 3000)
pt = floor(ep * flameMult)
```

一局真实结算的逐项对账（`team_vs_bestdori.mjs` 的 `[8]` 固化了这条）：

| 项 | 值 |
| --- | --- |
| 基本 + 得分奖励 | 120 + floor(1,747,439/15,000) = 236 |
| × (1 + 148%) | floor(236 × 2.48) = 585 |
| + 支援 floor(234,012/3,000) | 78 |
| 合计 | 663 |
| × 40 火 | **26,520**（与结算界面一致） |

⚠️ **先排序、后按角色去重**，顺序不能换。反过来会把「卡号最小」的那张留下
（池子是卡号升序），实测选中一批 2★（综合力 16,765）而不是三围最高的 5★（46,200），
支援综合力少 65%。

### 谱面数据的口径

`docs/data/charts/` 里是 `{d, n, s, f}` 精简格式，由 `scripts/fetch_charts.py` 生成：

- `d` 最后一颗音符的时间（秒）
- `n` 每颗计分音符的时间
- `s` 技能触发点在 `n` 里的下标（**全库 2437 个谱面全部恰好 6 个**）
- `f` Fever 区间（秒，闭区间，**含起止端点**）

**连击数 ≠ 谱面事件数**，这是最容易错的地方：

| 类型 | 算几个连击 |
| --- | --- |
| Single / Flick / Directional | 1 |
| Long | **2**（头 + 尾） |
| Slide | **`len(非 hidden 的连接点)`** |

`hidden: true` 的连接点是渲染插值，不是连击点 —— 全算进去会让连击数虚高 84%。
